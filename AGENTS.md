# AGENTS.md

## Project Shape
- This is a Drupal 11 + CiviCRM base project, not a custom app with source modules checked in yet.
- The public document root is `web/`; it is generated by Composer/Drupal scaffold and is ignored except for intentional custom code paths.
- `settings.php` lives at the repo root and the Docker build copies it to `web/sites/default/settings.php`.
- Docker Compose runs two services: `web` from the local `Dockerfile` and `db` from `mariadb:10.11`.

## Commands
- First local setup: `cp .env.example .env`, then edit `.env` values, especially `DRUPAL_HASH_SALT`.
- Full local build/run: `docker compose up -d --build`.
- Validate Compose without starting services: `docker compose config`.
- Check running services: `docker compose ps`.
- Follow app logs: `docker compose logs -f web`; database logs: `docker compose logs -f db`.
- Local URL defaults to `http://localhost:8080`; override via `PORT` in `.env`.

## Dependency And Generated Files
- `composer.json` is the source of truth; there is currently no `composer.lock` in this repo.
- The Docker build copies only `composer.json` before `composer install --no-dev --no-interaction`, so dependency resolution happens during image build unless a lockfile is added intentionally.
- Do not commit generated Composer/Drupal artifacts ignored by `.gitignore`: `vendor/`, `web/core/`, `web/modules/contrib/`, `web/themes/contrib/`, `web/profiles/contrib/`, `web/libraries/`, or `web/sites/*/files/`.
- Do not commit `.env`; use `.env.example` for documented defaults.

## Runtime Configuration
- Database connection values come from `DB_HOST`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME`; Compose sets `DB_HOST=db` for the web container.
- CiviCRM Compose variables point to the same MariaDB database as Drupal by default.
- Apache serves `/var/www/html/web`; do not change paths assuming `/var/www/html` is the document root.

## Verification Notes
- No CI workflow, PHPUnit config, PHPCS config, PHPStan config, or task runner is present in the repo.
- For infrastructure-only changes, use `docker compose config` as the focused check.
- For Dockerfile, Composer, or runtime config changes, prefer a smoke check with `docker compose up -d --build` and `docker compose ps`.
